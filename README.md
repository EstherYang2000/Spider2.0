# ReCAPAgent: LLM-Based SQL Generation with Self-Refinement

This document describes the **ReCAPAgent** system implemented in the Spider2-Lite framework, which enhances SQL query generation through iterative improvement, prompting, and adaptive weighted majority voting.

## ReCAPAgent Architecture

![ReCAPAgent Architecture](methods/spider-agent-lite/figs/ReCAPAgent_Architecture.png)

Expanding upon the Spider-Agent, we develop the **ReCAPAgent-SQL pipeline**. This approach integrates multiple specialized agents focused on:

- **PlannerAgent**: Generates step-by-step plans for SQL query construction
- **RetrieverAgent**: Performs retrieval-augmented generation (RAG) for external knowledge and syntax documentation
- **CritiqueAgent**: Analyzes and critiques generated SQL queries for potential issues
- **SchemaLinkerAgent**: Explores and links database schemas to improve query understanding
- **ActionAgent**: Executes SQL queries and handles database interactions
- **SelfRefinerAgent**: Iteratively refines SQL queries based on critique feedback
- **ValidatorAgent**: Validates query results and ensures correctness

## Overview

The ReCAPAgent system is designed to improve the quality and accuracy of SQL queries generated by language models through a sophisticated multi-agent pipeline. The system works by:

1. **Planning Phase**: PlannerAgent breaks down complex queries into manageable steps
2. **Initial Generation**: ActionAgent creates base SQL queries using prompting techniques
3. **Schema Integration**: SchemaLinkerAgent explores database structures and links relevant schema information
4. **Knowledge Retrieval**: RetrieverAgent fetches external knowledge and syntax documentation via RAG
5. **Critique & Analysis**: CritiqueAgent identifies potential issues in generated queries
6. **Iterative Refinement**: SelfRefinerAgent refines queries based on critique feedback
7. **Validation**: ValidatorAgent verifies query results and correctness
8. **Adaptive Voting**: Combines multiple approaches using weighted majority voting for optimal results

## Components

### run.sh
This shell script orchestrates the entire self-refinement process. It:

1. Activates the required environment
2. Runs experiments with specified models
3. Processes and evaluates results
4. Generates submission data

Example usage:
```bash
./run.sh
```

### self-refinement.py
The core implementation of the self-refinement mechanism. Key features:

- Query analysis and improvement
- Error detection and correction
- Integration with language models
- Result validation

## Configuration Options

The system can be configured using various command-line arguments:

- `--model`: Specify the language model (e.g., gpt-4.1-2025-04-14)
- `--self_refinement`: Enable self-refinement
- `--plan`: Enable planning
- `--rag_syntax`: Enable RAG syntax
- `--validate_result`: Enable result validation
- `--overwriting`: Allow overwriting existing results

Example configuration:
```bash
python run.py --model gpt-4.1-2025-04-14 -s test8 --example_index 32-33 --self_refinement --plan --rag_syntax --validate_result --overwriting
```

## Usage Example

1. Activate the environment:
```bash
source methods/spider-agent/spider2/bin/activate
```

2. Run the experiment:
```bash
cd methods/spider-agent-lite
python run.py --model [model] -s [suffix] --example_index [index] --self_refinement --plan --rag_syntax --validate_result --overwriting
```

3. Process results:
```bash
python get_spider2lite_submission_data.py --experiment_suffix [folder] --results_folder_name ../../spider2-lite/evaluation_suite/[folder]
```

4. Evaluate results:
```bash
cd ../..
cd spider2-lite/evaluation_suite
python evaluate.py --result_dir [folder] --mode exec_result --max_evaluate_num [num]
```
