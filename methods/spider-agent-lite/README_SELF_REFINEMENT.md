# Self-Refinement for Spider-Agent-Lite

This document describes the self-refinement mechanism implemented for Spider-Agent-Lite, which allows the agent to iteratively improve SQL queries based on execution results.

## Overview

The self-refinement mechanism is designed to improve the quality of SQL queries generated by the agent by:

1. Executing an initial SQL query
2. Analyzing the execution results
3. Refining the query based on the results
4. Repeating until termination conditions are met

This approach is inspired by the ReFoRCE (Self-Refinement Agent with Format Restriction and Column Exploration) workflow, which implements a self-refinement process with specific termination conditions.

## Termination Conditions

The self-refinement process continues until one of the following conditions is met:

1. **Self-consistency**: The same reasonable answer is achieved twice (non-empty, non-error results that are equivalent)
2. **Maximum iterations**: A predefined maximum number of refinement iterations is reached
3. **Consecutive empty results**: Two consecutive empty results are obtained

## Implementation

The self-refinement mechanism is implemented in the `SelfRefinementAgent` class, which extends the base `PromptAgent` class. The key components are:

- `SelfRefinementAgent`: Main class that handles the refinement process
- `RefinementResult`: Data class to store the result of each refinement iteration
- `perform_self_refinement()`: Core method that implements the refinement loop

## Usage

### Command Line Arguments

The following command line arguments have been added to enable and configure self-refinement:

- `--self_refinement`: Enable self-refinement for SQL queries (flag)
- `--max_refinement_iterations`: Maximum number of refinement iterations (default: 5)

### Example Usage

```bash
# Run with self-refinement enabled
python run.py --model gpt-4o --self_refinement --max_refinement_iterations 3 --example_index 0

# Use the test script
python test_self_refinement.py --model gpt-4o --example_index 0
```

## How It Works

1. When a SQL query action is detected, the `perform_self_refinement()` method is called
2. The initial query is executed and the result is analyzed
3. If refinement is needed, a prompt is generated for the LLM to refine the query
4. The refined query is executed and the result is analyzed
5. Steps 3-4 are repeated until a termination condition is met
6. The best result is returned (prioritizing non-error, non-empty results)

## Refinement Prompt

The refinement prompt includes:
- The current SQL query
- The execution result
- Previous refinement attempts (if any)
- Instructions based on the current situation (error, empty result, etc.)

## Output

The refinement process is logged, and the final result includes:
- The refined SQL query
- The execution result
- Refinement information in the trajectory

## Future Improvements

Potential improvements to the self-refinement mechanism:

1. More sophisticated result comparison for self-consistency
2. Better error analysis to provide more specific refinement instructions
3. Learning from past refinements to improve initial query generation
4. Support for more complex SQL features and database types
5. Integration with external knowledge sources for better refinement
